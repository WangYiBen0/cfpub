# AGENTS.md

Guidance for agents working in this repo.

## What this is

`cfpub` publishes local services through a Cloudflare Tunnel, addressed by path
(`https://<domain>/<machine>/<service>`). Two files, no dependencies beyond
`bash`, `curl`, `jq`, `cloudflared` and `python3`.

```
cfpub.sh          CLI: credentials, API calls, ingress rewriting
cfpub-proxy.py    HTTP/1.1 reverse proxy that strips the path prefix
routes.json       proxy route table (gitignored, regenerated by `pub`)
```

The tunnel is `config_src=cloudflare`, so ingress rules live in the API, not in
a local config file. That is why publishing needs no reload — and why `cfpub.sh`
is a script rather than a declarative module.

## Design constraints (do not break these)

1. **Publishing must never require a restart.** The proxy re-reads `routes.json`
   by mtime and the connector picks up ingress changes from the API on its own.
   Anything that needs a bounce is a regression.
2. **`pub` writes DNS before ingress, `rm` removes ingress before DNS.** A record
   without a rule yields a 404; a rule without a record is an invisible black
   hole that looks like nothing happened.
3. **The ingress list must end with an unfiltered rule.** Cloudflare rejects it
   otherwise (error 1056). Order is: path rules (longest first), then
   hostname-only tails for other subdomains, then the apex catch-all into the
   proxy, then any legacy unfiltered rule the operator put there, then
   `http_status:404`.
4. **A rule is identified by `(hostname, path)`, never by `path` alone.** One
   tunnel can serve several machines, and every machine publishes the same
   shape of path (`/<machine>/<service>`). Select, dedupe and delete on the
   pair, or `pub`/`rm` on one machine will silently drop or duplicate another
   machine's rules. This is why `rewrite_ingress` keeps foreign rules verbatim
   and `ls` prints a hostname column.
5. **No secrets in the repo, and none on a command line.** Credentials come
   from `~/.cloudflared/cert.pem` at runtime; the tunnel token only ever lives in
   a `0600` temp file, and the API token reaches `curl` through `-K` on a file
   descriptor because `/proc/<pid>/cmdline` is world-readable.
6. **Comments explain *why*.** The code is short; the reasoning is the value.
7. **`run`'s two halves stay independent.** `--connector` must not need
   `python3`, a route table, or anything HTTP; `--proxy` must not need
   credentials or `cloudflared`. `main` therefore loads credentials *after*
   parsing the selectors, and only when the connector is actually starting.
   Breaking that coupling is what makes proxy-only usable before `tunnel login`.

## Testing

**This tool operates on a live Cloudflare zone.** There is no staging account.
Every `pub` creates a real DNS record and mutates real ingress on a tunnel that
may be serving something you care about.

Safe procedure:

```bash
# 1. Snapshot the current state so you can prove you restored it.
./cfpub.sh ls
# (also capture the raw ingress, see below)

# 2. Use a throwaway service name, never an existing one.
./cfpub.sh pub testtmp 8099

# 3. Serve something identifiable on that port, then exercise it end to end.
curl -sS https://<domain>/<machine>/testtmp/

# 4. Always clean up, and re-check.
./cfpub.sh rm testtmp
./cfpub.sh ls
```

Raw ingress, for before/after comparison:

```bash
tok=$(sed -n '/BEGIN ARGO/,/END ARGO/p' ~/.cloudflared/cert.pem \
      | grep -v -- '-----' | tr -d '\n' | base64 -d)
api=$(jq -r .apiToken <<<"$tok"); acct=$(jq -r .accountID <<<"$tok")
curl -sS -H "Authorization: Bearer $api" \
  "https://api.cloudflare.com/client/v4/accounts/$acct/cfd_tunnel/<id>/configurations" \
  | jq -c '.result.config.ingress'
```

For SSH, note that authentication is a separate problem from routing. Getting
`Permission denied (publickey,...)` back means the tunnel works — it reached the
real sshd. `websocket: bad handshake` or `530` means no connector is running.
That is also the quickest way to tell the two halves apart: `run --connector`
should make SSH work while HTTP paths still fail, and vice versa.

Lint before committing:

```bash
shellcheck -s bash cfpub.sh
python3 -m py_compile cfpub-proxy.py
bash -n cfpub.sh
```

## Traps found the hard way

These all cost real debugging time. Do not reintroduce them.

- **A dropped TLS handshake is not an API error.** Cloudflare returns HTTP 200
  with `.success: false` for real failures, so `api_ok` checks the body and
  retries only connection-level failures (`CFPUB_RETRIES`). Do not retry a
  `.success: false` — it just repeats the same rejection.
- **`cloudflared` does not strip the ingress `path` prefix.** It forwards the
  full path. That is the entire reason `cfpub-proxy.py` exists; an HTTP service
  published without it 404s.
- **jq chained binds silently break `unique_by`/`sort_by`.** A program shaped
  like `def f: ...; [ ... ] as $x | (... | unique_by(.path))` fails with
  "Cannot index array with string", because the filter receives the *array*, not
  its elements. Bind each stage to its own `$var` first. This is why
  `rewrite_ingress` has separate `$kept` / `$paths` / `$sorted`.
- **Sorting ingress rules by path length alone is unstable.** `sort_by(-(.path |
  length))` leaves ties in arbitrary order, and a path-only rule for the same
  prefix would then shadow the hostname-scoped one. That is why the sort key is
  `[-(.path | length), (has("hostname") | not), (.hostname // "")]`.
- **`pkill -f <anything>` kills the calling shell when the pattern appears in
  its own command line.** Bites with `cfpub-proxy.py` *and* with
  `cloudflared tunnel`. Use `pkill -x cloudflared` (process name only) or kill
  the pid the script recorded.
- **`~/.local/state` is not always writable** (containers, read-only `$HOME`).
  `default_state` probes and falls back to `/tmp/cfpub` then `./cfpub`; keep
  both the probe and the fallbacks.
- **`$SELF_DIR` must stay assigned before `default_state` is called.** It is
  used inside the function body; bash would resolve it fine either way, but
  keeping the assignment first removes the ordering question entirely.
- **`pub ssh 22` publishes HTTP**, not SSH. A bare port always means HTTP by
  design; SSH needs the explicit `ssh://localhost:22`.
- **The proxy must not pass framing through.** It used to read only
  `Content-Length` and ignore `Transfer-Encoding`, so a chunked request left its
  payload on the socket, and the HTTP server parsed that payload as *the next
  request* — which the proxy then routed to whichever prefix it named. One edge
  request to a public path could reach a protected path's origin, straight past
  path-scoped Access rules. Refuse `Transfer-Encoding` and conflicting
  `Content-Length`, and never reuse the connection.
- **A path is not a sandbox if `..` reaches the origin.** `/prefix/../admin` is
  normalised by nginx `alias`, SPA fallbacks and `SimpleHTTPRequestHandler`, so
  the origin serves a directory the operator never published. Reject dot
  segments before selecting a route.
- **`mkdir -p` is not a writability probe.** It succeeds on any existing
  directory, so an unwritable state dir was selected and `pub` failed only after
  DNS and ingress were committed. Probe by writing, and check the directory is
  owned by this user and not group/other-writable — whoever owns it can rewrite
  the route table into an SSRF.
- **`jq ... > "$STATE.tmp"` follows symlinks.** A predictable temp name in a
  shared directory lets another user point it at a file of their choosing and
  have `pub` overwrite it. Use `mktemp` in the same directory, then rename.

## Style

- `set -euo pipefail`; every expansion quoted; `local` for every function
  variable.
- Messages to the user go to stderr (`warn`), machine-readable output to stdout,
  so `ls` and `token` stay pipeable.
- Fail with a message that says what to do next, not just what went wrong.

## Scope

Deliberately out of scope: process supervision (`run` is foreground on purpose),
wildcard certificates, Cloudflare Access provisioning, and multi-host
orchestration. If you need any of those, wrap cfpub rather than growing it.
